# Documentation

API reference is the rustdoc of each crate (`cargo doc --open`); start at the `engine` crate. This folder holds the rest: why things are the way they are, how they were designed, and what was measured.

## What is here

| Path | What it is | Kind | How far to trust it |
|---|---|---|---|
| [`roadmap.md`](roadmap.md) | Milestones, their exit criteria, and the current milestone's chunks with their status | Reference | **Authoritative for what is planned and its status.** |
| [`adr/`](adr/) | Architecture decision records: one short file per decision that is hard to reverse (context, decision, consequences) | Explanation | **Authoritative.** Each has a `Status` line. A later ADR may supersede an earlier one. |
| [`design/`](design/) | One folder per milestone, containing one folder per chunk with its `spec.md` and `plan.md`; [`_template/`](design/_template/) holds the templates. `m0-m1-foundations/` predates chunks and holds one spec and one plan for the whole milestone | Explanation | The **spec** is a living design document: where it differs from the code or an ADR, the code and the ADR win. A **plan** is a historical record once its pull request merges. |
| [`maintainers.md`](maintainers.md) | Repository settings and the checklists for going public and merging | How-to | Operational; update it when the process changes. |
| [`benchmarks.md`](benchmarks.md) | Methodology, hardware, results, and what the numbers do and do not show | Reference | Evidence for specific claims on one machine; read its caveats before quoting a number. The marked data sections are generated by `cargo xtask bench-doc`; the analysis is hand-written and checked against them. |
| [`data/`](data/) | Small inputs to generated docs: the machine and run conditions recorded when each benchmark run started | Reference | As recorded. |

Rules that are checked mechanically (lints, `unsafe`, determinism bans, workflows) live in the tooling and in [CONTRIBUTING.md](../CONTRIBUTING.md), not here. Reporting a vulnerability is in [SECURITY.md](../SECURITY.md).

## Conventions

- **Every document states its status** near the top: `Draft`, `Accepted`, `Amended`, `Implemented`, `Superseded` or `Historical`, with a date.
- **ADRs** are `adr/NNNN-kebab-title.md` with Status, Context, Decision and Consequences. Add one for any decision that would be expensive to reverse. Do not rewrite an accepted ADR to change the decision; write a new one that supersedes it.
- **Design folders** are `design/m<N>-<topic>/m<N>.<n>-<topic>/`, holding the chunk's `spec.md` and `plan.md`, copied from [`design/_template/`](design/_template/). A spec keeps stable section numbers because code and config cite them (for example "spec §4.9"); add sections, do not renumber.
- **Plans are kept.** A plan is written before implementation and records what differed in its Deviations section. When its pull request merges, its status becomes `Historical`: it records how the work was done, and the spec, the ADRs and the code are authoritative.
- **Milestone numbers changed on 2026-11-12.** Documents dated before then (the M0+M1 spec, ADRs 0001 to 0011, `benchmarks.md`) use the old numbers; [the roadmap](roadmap.md) has the mapping.
- **Prefer a link to a copy.** If a rule is enforced by a command, document the command and let the tool be the source of truth.
- **Numbers need provenance.** A benchmark claim says what was measured, on what machine, in what conditions, and what was not measured.
